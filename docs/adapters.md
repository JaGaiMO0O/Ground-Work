# The adapter contract

The control plane is stack-agnostic on purpose. It knows about git, YAML, paths
and markdown - nothing else. It does not know how to talk to Oracle 11g, replay
a SOAP envelope, or convert a proprietary binary format.

Everything that touches a live system goes through an **adapter**: a small
executable you own, declared per system in `project.yaml`.

```yaml
adapters:
  db: oracle          # -> scripts/adapters/db/oracle.sh
  capture: rest       # -> scripts/adapters/capture/rest.py
  test: none          # this system has no replayable boundary
```

A dispatcher (`snapshot_db.py`, `query.py`, `capture.py`, `test_golden.py`)
resolves the name, builds the environment, and execs it. That is the whole
mechanism.

---

## Why this indirection exists

Estates are not one stack. A single engagement can span Java on
a Postgres warehouse, packages living inside a database, and a .NET
service somebody added in 2018. Writing `snapshot-db` for "the database" bakes
in an assumption that breaks on the second system.

The adapter boundary keeps the expensive, portable part - cards, contracts,
validation - reusable, and confines the stack-specific part to a file you can
rewrite in an afternoon.

## Invocation

```
<adapter> <verb> --system <name> [--out <path>] [extra flags]
```

The dispatcher always passes `--system`. Everything else depends on the verb.

### Verbs by family

| Family | Verb | Produces |
|---|---|---|
| `db` | `schema` | DDL snapshot -> `map/<sys>/schema.sql` |
| `db` | `erd` | Mermaid ER diagram -> `map/<sys>/erd.mmd` |
| `db` | `query` | Rows on stdout, from a read-only statement |
| `capture` | `record` | Raw observed traffic -> `integration/fixtures/<sys>/raw/` |
| `capture` | `contract` | OpenAPI/JSON Schema -> `integration/contracts/<sys>.v0.yaml` |
| `capture` | `fixtures` | Golden-master pairs -> `integration/fixtures/<sys>/` |
| `test` | `run` | Replays fixtures, reports equivalence |

An adapter that does not implement a verb exits **3**. That is a normal answer,
not a failure - a system with no observable boundary genuinely has no `record`.

## Environment

The dispatcher loads `.env` into the **child process environment** and execs the
adapter. Adapters read credentials from the environment; they never parse
`project.yaml`, and they never need a YAML library.

> `.env` is read by the dispatcher, never by an agent, and its values are never
> printed, logged, or returned on stdout. That is the whole reason credentials
> go through this path instead of onto a command line.

Every adapter receives:

| Variable | Meaning |
|---|---|
| `PROJECT_ROOT` | absolute path to the control repo |
| `AREA_NAME` | the declared system name |
| `AREA_KIND` | `repo`, `database`, or `fileshare` |
| `AREA_REF` | the pinned ref, empty for non-repo systems |
| `AREA_CHECKOUT` | absolute path to `systems/<name>` |
| `AREA_CARD_DIR` | absolute path to `map/<name>` |
| `AREA_SCHEMA_OWNERS` | comma-separated, from `schema_owners:` |
| `AREA_DATABASE` | `stack.database`, e.g. `oracle11g` |

Plus everything in `.env`.

## Exit codes

Meaningful exit codes are the contract. The dispatcher translates them for the
human, so get them right.

| Code | Means | Dispatcher behaviour |
|---|---|---|
| `0` | success | reports the artifact written |
| `3` | **not applicable** - this verb does not exist for this system | reports it as normal, not an error |
| `4` | **missing credentials or configuration** | tells the user which variable to set |
| `5` | **upstream unavailable** - DB down, endpoint unreachable | suggests retrying |
| `1` | anything else | reports failure |

Never use `1` where `3` or `4` is accurate. The difference between "this cannot
work here" and "this is broken" is the difference between a team moving on and
a team debugging for an hour.

---

## Rules every adapter must follow

1. **Read-only.** No DDL, no writes, no side effects on the target. If an
   adapter can modify an external system, the read-only guarantee this repo
   rests on is gone.
2. **Idempotent.** Running twice produces the same artifact.
3. **Never print secrets.** Not on stdout, not on stderr, not in an error
   message. Redact connection strings before logging them.
4. **stdout is data, stderr is for humans.** `--out` writes to a file; without
   it, data goes to stdout so it can be piped.
5. **Stamp generated output.** Every artifact starts with a `GENERATED` header
   naming the adapter and the re-run command. `check.py` enforces this, because
   an unmarked generated file eventually gets hand-edited.
6. **Enforce timeouts.** A statement timeout on every query, without exception.

### Header format

Use the target format's comment syntax:

```sql
-- GENERATED by scripts/adapters/db/oracle.sh on 2026-07-27
-- Source: reporting-db (ANALYTICS). Do not hand-edit.
-- Re-run: python scripts/snapshot_db.py reporting-db
```

## What ships here

| Adapter | State |
|---|---|
| `db/postgres.sh` | working reference |
| `db/oracle.sh` | working reference - **validate against your instance before trusting it** |
| `capture/rest.py` | working reference: recording proxy, contract reduction, fixtures |
| `db/_stub.sh`, `capture/_stub.sh`, `test/_stub.sh` | honest stubs, exit 3 |

There is deliberately no SQL Server, DB2, or SOAP adapter. Shipping one that
had never been run against a real instance would be worse than shipping
nothing: a stub tells you it is a stub, and a broken adapter tells you your
schema is empty.

## Writing your own

Copy the nearest reference, keep the exit codes, and run:

```bash
python scripts/check.py
```

`check.py` fails if `project.yaml` names an adapter that does not exist on
disk, so a typo in a system's `adapters:` block surfaces immediately rather
than the first time someone runs a capture.
